DBTLHub · Project 25 · bioprospecting

Where the agents sit, and what they keep

A walk through one turn of the Design–Build–Test–Learn cycle for enzyme bioprospecting: what happens at each step, what the checking agent at each boundary does, the two places a language model is allowed to act, and how the record grows into one graph that still answers, at the far end, where a sequence came from.

First, the three words

Phase. The science: finding enzymes, making them, measuring them, learning from the numbers. We did not change any of it.

Handover. The moment one phase passes its work to the next. There are four in a cycle, and this is where things get lost.

Sentinel agent. A small program sitting at one handover. It reads what arrived, decides whether the next phase can accept it, and is allowed to say no.

A phase does the work. A sentinel decides whether the work can travel.

The path, step by step

  1. phase

    Design — find the candidates

    Sediment is collected, DNA is extracted and sequenced, the reads are assembled, genes are predicted and annotated, similar proteins are clustered, and 96 are chosen. Eleven steps, each one recorded.

    produces
    an RO-Crate: a folder with the sequences, plus one file saying what everything is and what produced it
    a model?
    no
  2. H1

    Design → Build AI may draft

    The synthesis vendor needs almost nothing: a list of sequences and which well each goes in. Everything else — where the sediment came from, the freezer temperature, who held the corer — stays with us. So this agent has two jobs: cut the order down, and make sure what stays is still usable.

    checks
    that every key the lab invented has an agreed term; that numbers carry their units; and, the one that matters, that every sequence has an unbroken path back to a physical sample
    refuses
    a sequence with no origin a site with no coordinates a file the crate promises and does not contain
    flags
    a protein the crate honestly records as a truncated gene. The crate is correct, so it is not refused — but the plate goes out with that well marked
    into the graph
    385 triples the whole Design record, including the eleven steps back to the sediment
  3. phase

    Build — make them

    The vendor synthesises, the lab assembles, a liquid handler fills a 96-well plate, an instrument runs quality control on each well.

    produces
    a plate map and QC readings
    a model?
    no
  4. H2

    Build → Test AI may draft

    Design said which 96 wells it wanted. Build says what actually arrived. The agent computes the difference — and a failed synthesis is a perfectly normal outcome, it just has to be stated.

    checks
    no two samples claim the same well; nothing arrived that Design never asked for; every required measurement has its unit; and nothing Design asked for is quietly missing
    refuses
    a well silently absent two samples in one position a measurement with no unit
    into the graph
    → 475 each sample, joined to the design item it was built from
  5. phase

    Test — measure them

    Cells are grown, the assay is run, a plate reader produces a number per well against its blank and its controls.

    produces
    one reading per well, with the method that produced it
    a model?
    no
  6. H3

    Test → Learn AI may draft

    A model is about to be fitted to these numbers. The agent's job is to make sure each number can be traced to the well it came from and says what it is.

    checks
    every result resolves to something Build actually made, and carries unit and method
    refuses
    a measurement nobody took a duplicate sample id
    into the graph
    → 520 each reading, joined to the sample it was read from
  7. phase

    Learn — decide what to make next

    A model is fitted to the results and ranks what to try in the next round.

    produces
    ranked recommendations with predicted values
    a model?
    yes — but this is the science's own model (a protein language model, a regression), not the agent's. The agent never touches it; it only checks what comes out
  8. H4

    Learn → Design AI may draft

    This handover carries the one thing in the cycle that is not a measurement of something that happened: a claim about something that has not happened yet. So the contract asks the three questions that make such a claim checkable.

    checks
    what does it rest on — every recommendation names result ids that must exist in the data it claims to have learned from; what produced it — model name, version and training runs, because "latest" is not a version; how sure is it — uncertainty is required, and must say what kind it is
    refuses
    a reason citing a measurement that does not exist a prediction with no uncertainty
    does not check
    whether the recommendation is any good. That is next round's job, and the model's holdout score travels along so the two can be compared. Traceable, reproducible and weighable are checkable; being right is not

Where a language model is allowed to act

Two places in the whole framework. Nothing reads an API key, and the default path never calls a model at all — the demo runs on a laptop with no network.

WhereWhat it may doWhat stops it
Naming a word nobody agreed
propose_terms		 The lab wrote box_temp_c. No query can use that. A model can work out it means a storage temperature — a rule cannot reason about a word it has never seen. It may only choose from terms the shared vocabulary already declares, and the answer is reported, never applied. The handover still fails until a human adds the line.
Repairing what is derivable
propose_patches		 Put back a unit the profile already states. Recompute a checksum. It is only shown errors that are safe to touch; it may only write where the validator pointed; and the package is re-validated afterwards, so it is never its own judge.

Measured, not asserted. On one invented key, with the same code: the Claude CLI and the Codex CLI both proposed the right term; a three-billion parameter model running locally proposed one nobody had agreed, and the framework rejected it. In every run the handover still failed, because a suggestion is reported and never applied.

Bring whichever model you like — a CLI you already log into, or one on your own laptop with no network at all: CommandEngine("claude"), CommandEngine("codex"), CommandEngine("ollama"). One argument, your own key or none.

A model may draft. It may not decide.

Why the graph matters

Handover 1 sends the vendor a sequence and a well. From that moment, the sampling site, the freezer and the collector are reachable only through what we wrote down. Two different checks keep that true, and both are needed.

Do the links resolve?

Every package names the package it was built from, and the first names the crate. trace.py walks a run backwards and fails if a link breaks. Running it the first time showed the chain had never been real: two phases were building the path of their own upstream package as a text string, and one of them named a file no run had ever written. Every package validated perfectly on its own. That failure is invisible to any check that looks at one package at a time.

Can you ask it a question?

A list of file paths is not something you can query. So every step appends to one graph per run, and the Design crate's own record joins the same file. By the end of a cycle, one graph holds the deep provenance of the Design phase and the spine linking the four handovers — which is how the walk in the picture above happens in one traversal instead of a tour of four files.

It is plain N-Triples on disk: no database, no server, and rdflib or pyoxigraph will load it unchanged when a real query engine is wanted. A new handover joins the graph for free.

If you are taking a handover

The loop every agent runs — reshape, validate, repair within a budget, escalate — is written once and inherited. Two of the four agents are three lines each with no logic at all. That is the normal case.

FileWhat it is for
template/TAKE_A_HANDOVER.mdRead this first. One page: the four decisions, in order
scripts/new_handover.pyScaffolds your contract and your agent with the shared parts already correct. Do not copy a file by hand
template/handover_agent.pyThe copy-me agent, with each decision marked
template/handover_contract.schema.jsonThe copy-me contract
scripts/show_agents.pyThe four as they are right now, read from the live code
scripts/check_crate.py --break-allHandover 1 against the use case's own crate, then the same crate broken three ways
scripts/prove_engine.pyThe model question, reproducible — part 3 needs no model
scripts/trace.py · scripts/ask.pyDoes the chain resolve; and ask the graph

The four decisions are: what crosses this handover (the contract), what your use case needs (the profile — this is where use cases are supposed to differ, so do not fork the contract), which errors must never be fixed automatically, and whether you need to reshape the incoming package at all (usually not).

On the third one, the test is not "is this hard to fix" but "would fixing it invent something nobody recorded". A guessed well writes a lab record that never happened, which is worse than a failed handover, because a failed handover is visible.

Running it

python3 demo_d2b.py                        # handover 1: a clean crate, then a broken one
python3 demo.py                            # design through to the test results
python3 demo_l2d.py                        # handover 4: the round that closes
python3 scripts/check_crate.py --break-all # on the use case's own crate
python3 scripts/ask.py demo-clean --behind BP1-A01
